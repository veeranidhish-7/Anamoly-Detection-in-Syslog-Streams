# Team Talking Points

**What is a log?**
A log is simply a text diary entry generated by a computer. Whenever a system runs a process, starts up, or encounters an error, it writes a timestamped sentence detailing what happened.

**What is an anomaly?**
An anomaly is an unusual pattern or event in the logs that deviates from normal operation. This usually indicates a system failure, misconfiguration, or security breach.

**What do PCA and RPCA do conceptually?**
PCA (Principal Component Analysis) learns the "normal recipe" of a system by counting how often certain log messages appear together. If a new sequence of logs has a drastically different count, it flags it as an anomaly. RPCA (Robust PCA) is a variation that separates data into a "normal" background matrix and an "anomalous" foreground matrix, making it more resistant to noisy training data.

**Why did the BGL dataset score lower than HDFS initially?**
HDFS is a highly structured, simple dataset where counting log frequencies (PCA) works perfectly. BGL is a massive supercomputer log dataset filled with complex, overlapping events. Simple counting math fails on BGL because it cannot understand the sequential order or the semantic meaning of the errors, which is why we had to introduce a Deep Learning Autoencoder.

**What is the single biggest current limitation of the project?**
We currently do not have an automatic model selector. Right now, a human has to manually choose whether to run the PCA model or the Autoencoder based on prior knowledge of the dataset. To be a true framework, the system must be able to automatically analyze the variance of a new dataset and choose the correct model by itself.

**What is the Word2Vec leakage issue?**
Our BGL text-embedding step technically got a sneak peek at the test data's vocabulary before testing began, even though it never saw the actual anomaly answers. So our real-world score is probably a little lower than 87%, and we're upfront about that.
